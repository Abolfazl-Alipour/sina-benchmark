# 0025 — Pathway Discovery Funnel: from gene ranker to mechanism finder

- **change:** Add the Pathway Discovery Funnel as the post-Wave 1 product layer. BioPathNet is a path-based GNN (6-layer NBFNet, `hidden_dims [32x6]`, `path_topk 10`, `aggregate_func pna`); current Wave 1 grades only the destination gene (`MRR 0.00781`, `p=0.376` directional). The funnel extracts gradient-weighted reasoning traces for the **Top-100** genes per disease (catches rank ~100 where `WRN` typically sits at `MRR 0.007→rank 128`), aggregates 1,000 paths per disease by intermediate `GO Biological Process (BPO-GEN 158k)` / `Reactome (PWY-GEN 46k)` / `12 Hallmarks of Aging` nodes already in the `1,431,945` KEEP graph, and scores **pathway-level recovery** (`pathway Recall@10`, `pathway MRR`) against ground-truth pathways derived from held-out test genes only. Top-50 stays the figure (`3×3` genes for organoid), Top-100 is the score, with `50/200` sensitivity. The funnel neutralizes the "expensive 2-hop SQL join" attack: multiple weak genes on one pathway sum to one strong pathway signal.
- **rationale:** Executive Summary 2026-08-22 pivot (§3) — rare diseases were the wind tunnel, not the product; sporadic AD/senescence is the product. Gene-level `Hits@10 0.2-2.2%` looks terrible at `MRR 0.007` but `100` genes at rank 100 sharing one `GO:0006914 autophagy` pathway is a testable hypothesis. The funnel also fixes `A3` triviality (`13/13 >10% ≤2 hops` on KEEP) by showing >2-hop pathway reasoning even when genes sit 2 hops away.
- **requester:** Owner 2026-08-22 Executive Summary + Aug 17 brutal review (pathway vs gene metric) + multi-model peer review 2026-08-22 (grain-of-salt synthesis)
- **prior art (honest citation, not novelty claim):** BioKGC/BioPathNet gradient-weighted path interpretation (Oleshko 2024 → Hu 2026) — reuse verbatim; Hetionet DWPC hub penalty (Himmelstein 2017) — `log(degree)` descendant; GSEA/ORA (Subramanian 2005) — standard enrichment. Novelty is *aggregation architecture* (Top-100 → 1,000 grad-weighted paths → hub-penalized pathway ranking with min-support) on OptimusKG LODO zero-shot with pre-registered nulls.

## Owner amendment 2026-08-24

Two owner-approved amendments, driven by verified findings from the frozen-spec HGPS run (seed-1337 checkpoint): extraction itself is fine (971 paths / 100 genes) and the faithfulness control PASSes (median score drop 0.119 after masking Top-10 paths, 100% of genes dropped), but the frozen aggregation is EMPTY — of 5,645 path edge-endpoints only 8 are GO nodes (max support 2) and 0 are Reactome. Unconstrained top-grad paths route through ASSOCIATED_WITH (other diseases' genes), INDICATION/ENZYME/TARGET (drugs), PARENT (disease hierarchy), and PHENOTYPE (HP) instead. **Headline honest-negative result (remains the frozen-spec headline): model explanations are drug/phenotype-mediated, not ontology-mediated.**

1. **Multi-seed consensus scoring.** Positive-control ranks vary sharply across seeds (WRN: seed1337=173, seed1339=70, seed-mean(1337,1339)=98; LMNA: seed1337=16, seed1339=57, seed-mean=17), so the single-seed Top-100 gate is fragile while the 2-seed consensus passes both controls. When `--checkpoint` is NOT passed, all available seed checkpoints matching `reports/m2b/checkpoints_wave1/{cs}_keep*_pass1.pth` are auto-discovered (`consensus.seeds: [1337, 1339, 5027]`; missing seeds skipped with a warning, so a 2-seed run works today). Genes are scored under EACH checkpoint separately; consensus ranking = mean sigmoid score across seeds (tie-break gene idx), defining Top-K selection AND the positive-control gate (per-seed and consensus ranks logged + reported). Path extraction runs per checkpoint for the consensus Top-K; per-seed tagged parquets (`__seed{N}.parquet`) plus the pooled union as the primary parquet; aggregation/evaluate/report consume the pooled union (per-K sensitivity unchanged). Explicit `--checkpoint` keeps single-checkpoint behavior (shuffle-collapse gate, debug). Open-world disease (`checkpoint: null`) stays single-run; consensus not applicable (logged).
2. **Ontology-anchored exploratory variant.** New `anchor` stage (after aggregate, before evaluate; report gets a clearly-labeled EXPLORATORY section, separate from the frozen headline numbers). Candidates = GO BP / Reactome nodes with a DIRECT train1 annotation edge (either direction, inverse folded) to at least one consensus Top-K gene — the only nodes that can mediate with a direct annotation suffix. Per seed checkpoint: one shared bellmanford pass conditioned on (disease, relation), then the best grad-weighted D→P prefix path per candidate via the same beam-search primitives (relation conditioning stays the disease-gene relation — disclosed approximation). `anchored_score(P,g,seed)` = best D→P prefix weight, valid only if the direct P—g edge exists in train1. Pathway score = (sum over top genes g and seeds of anchored_score) / ln(degree(P)) with degree(P) = train1 edges touching P (same pin as frozen spec); min_support 5 (sensitivity 3/5/10), support = distinct consensus Top-K genes with a valid (P,g). Anchored Recall@10/5 emitted against the same test-genes-only GO/Reactome ground truth as the frozen evaluation, clearly labeled exploratory. Disclosure carried in the report: unconstrained top-grad paths bypass ontology nodes (frozen result); this table answers which pathways WOULD mediate if paths were forced through them; prefix relation conditioning is an approximation; annotation edges are in train1 (circularity already disclosed).

The frozen-spec result remains the headline; the anchored table is post-hoc and exploratory and must never be quoted as the frozen endpoint.

### Addendum 2026-08-25 — anchored-stage performance fix

The first anchored-stage run (Werner) was killed after 4.3 h: the exhaustive per-candidate `beam_search_distance` (~15 s per candidate per seed, 3,239 candidates × 3 seeds ≈ 40 h/disease) is computationally infeasible, and `beam_search_distance` cannot batch targets (t_index must be scalar — it edge-masks edges starting at t). Owner-approved fix, implemented in `scripts/pod/extract_paths.py`:

1. **Support prefilter** (`anchored.min_candidate_support: 3`): candidates with support < 3 are dropped before any GPU work. Candidates below the strictest reported min_support sensitivity (3) can never appear in any reported table, so the reported tables are identical to exhaustive. Werner: 3,239 → 520 candidates.
2. **Viterbi best-path estimator** replaces per-candidate beam search: after computing edge grads exactly as before, the best D→P prefix weight is a max-sum DP over the step graphs (equivalent to `beam_search_distance` with num_beam=1, minus the t-masking), with backpointers for path reconstruction, vectorized per layer via `scatter_reduce`. Disclosed estimator differences from the gene-path beam extraction: single best path, no length averaging, no target edge-masking.
3. **Resume fix**: a run killed post-extract now rebuilds the solver on `--resume` (build_solver + load primary seed checkpoint) when the anchor and/or faithfulness stages have not completed, so they still run; extract is not rerun (parquets manifest-consistent).
